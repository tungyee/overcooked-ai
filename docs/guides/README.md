# 胡闹厨房 2（Overcooked! 2）关卡攻略库

面向 AI 2P 陪玩（`oc2`）规划的离线攻略库。每关一个 Markdown 文档，供后续「攻略读取」功能加载，帮助 AI 更好地规划任务与分工。

## 文档约定

每关文档按 `_template.md` 结构撰写，关键约定：

1. **关卡编号为主键**：文件名即人类可读编号（如 `story/1-4.md`、`kevin/3.md`）。未来「攻略读取」功能按此编号映射。
2. **内部关卡名**：插件上报的 `level`（如 `Sushi_1_4_2P`）记录在文档「内部关卡名」字段。命名规律为 `{主题}_{世界}_{关内序号}`（`_2P` 表示双人版），例如 `Sushi_1_4` = 主线 1-4、`Rapids_2_1` = 主线 2-1。代码中已知的内部名见各文档。
3. **星级门槛以 2P 为准**：本 AI 只玩双人分屏（玩家 = 人类，你 = AI），文档记录 2P 的 1~4 星分数门槛。
4. **视角表述**：面向 AI 的攻略统一用「你（AI）/ 玩家（人类）」，避免出现会被 TTS 念出来的内部代号。
5. **攻略重点**：AI 已能实时读到菜谱、订单、站点坐标，所以文档重点放在**无法从快照直接推导的内容**——打法分工、流程顺序、投掷点、陷阱与关卡机制。

## 攻略读取

- 代码在 `ai/dialog/cookbook.py`：开局按插件上报的 `level` 匹配每关「内部关卡名」；主线找不到时再按 `{主题}_{世界}_{关}` 回退到 `story/{世界}-{关}.md`。
- 插件 `level` 是 Unity 关卡资产名，**不等于 UI 编号**：实机 UI 3-3 上报的是 `Wizard_3_2_2P`（与 UI 编号差 1）。映射以文档「内部关卡名」为准，不按资产名里的数字猜关卡号。
- system prompt 注入「关卡机制 / 打法与分工 / 陷阱」摘要；模型需要细节时调用 `read_cookbook(section)`。
- 文档里统一用「你」指 AI、「玩家」指人类队友；运行时不再做内部代号转换。`tests/test_guide_person.py` 会拦住残留的内部代号。
- DLC 关如果没写内部关卡名，暂时无法自动命中；可在文档「元信息」里补 `内部关卡名`。
