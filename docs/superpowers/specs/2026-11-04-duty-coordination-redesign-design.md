# 分工协调模型重构：动作级分工 + planner 单一权威（判 / 做 / 分工 / 禁）

日期：2026-11-04
状态：草稿，已过 builder review，待你核对 §7 判断后定稿

## 1. 意图（为什么做）

现有「谁做什么」的协调模型有三个症状，且是同一个根因：

1. **按物料认领在分割图上物理不可行**。`update_duties` 的 `target=物料` 表示「认领这种料的
   整条加工链」（`ai/dialog/duties.py`）。但 2-1（Rapids_2_1）里薯条/鸡块链横跨
   「厨房料箱 → 木筏砧板 → 厨房炸锅」，任何一人无法独自跑完一条链；「只负责薯条不负责鸡块」
   会让鸡块（砧板只在 P2 的木筏）永远切不了，组合单 `ChickenNuggetsAndChips` 永远上不了。

2. **`help_request` 喊了 P2 还是自己做**。它的「别做」复用软 claim 偏好（`kind="claim"`、
   weight `-1.0`），被订单紧迫度、L0–L2 顶层负分免疫、截止闸放行三条路轻易压过（
   `ai/core/planner.py` 的 `_matching_preferences` / `_clear_claimed_commitment` / 截止闸）。

3. **`help_request` 与 `update_duties` 割裂**。两者最终都写进同一个 `Ledger`、编译成同一批
   `Preference`，但决策者、触发、粒度、档位、生命周期、LLM 角色全部不同：speech 回合 LLM 是
   「决策者」（`tool_choice="auto"` 写账本），help_request 回合 LLM 是「代言人」
   （`tool_choice="none"` 只措辞）——**两个权威、两套词汇回答同一个「谁做」问题**。

关卡普查（有帧/文档的 15 关、有布局的 14 关）证实：**8 张分割图按物料分工硬性不可行、
3 张连通但站点错位低效、只有 3 张对称教学关安全**。而游戏里「动作 = 站点 = 边」三者同构
（切↔砧板↔木筏侧、炸↔炸锅↔厨房侧），所以分工单位应该从「物料」换成「动作」。

## 2. 目标 / 非目标 / 反目标

### 目标

- **判（校验）**：P1 的每个请求，planner 用物理证据（可达性、菜谱是否有这道菜/料）判可
  行性；做不到时 LLM 如实回话，而不是盲写账本。
- **做（立即执行）**：P1 的祈使（「去切黄瓜」）不是往账本加软偏好等 planner 慢慢选中，
  而是 planner **当场选对 task 立刻执行**（硬指令）。
- **分工（持续 follow）**：P1 的分工（「你负责切我负责炸」）是**动作级**（=站点）约束，
  planner 校验落地后持续 follow；**双向**：P1 说「我来切」= P1 负责、P2 避开（见 §7.1）。
- **禁（stop）**：P1 说「先别做」→ 硬压制 + TTL，补齐现在缺失的「禁」行为。
- **撤销/覆盖**：「算了别切了」「不是切是下锅」这类改口，要有撤销/覆盖语义（从
  `update_duties` 的 `edit/remove/同 target 改写` 三件套搬过来，不随 tool 一起丢）。
- **统一 P2→P1 请求与 P1→P2 指派**：两者是同一个 request/assignment 概念，只是方向不同
  （speech 发起 vs planner 发起）。

### 非目标（本期不做）

- 不做**物料级分工**：物料不做分工单位。`assign`（分工）纯动作、v1 不加 material 字段；
  只有 `now`/`stop` 带**可选 item 限定**用于选对 task（这是「动作×料」的罕见修饰，见 §7.2）。
- **取料/搬运不暴露给 LLM**：由 planner 按「料源可达性」自动归位（见 §5.3）。
- **投掷/渡运不算分工单位**：它是跨边交接的「接缝」，谁手里有料谁投（见 §5.4）。
- 数量/序列（「洗 2 个盘」「先切再煮」）不做（沿用 2026-11-02 期的结论）。
- P2 过载主动甩活（「我忙不过来你帮我」）不做：这是软缺口，需要一个「P2 过载」判据，
  留后续。

### 反目标（即使技术可行也算失败）

- 不能回到「LLM 有决策权」：LLM 只提意图，planner 是「谁做」的唯一权威。
- 「别做」不能像现在的 claim 那样软（否则又喊了照做）。
- 「补位」不能靠 -1.0 软权重默认漏给 P2，要靠显式截止闸在订单真要崩时放行。
- 不动 P1 的行为（P1 是玩家；机制只「说话 + 改 P2 自己的计划」）。
- 救援动作（灭火/救糊锅/端快糊的锅）永不触发「别做」、也永不因分工被压制。

## 3. 约束

- **对话层线程边界**（AGENTS.md）：主循环 20Hz 是唯一碰 `World`/`Blackboard` 的地方；
  `ai/dialog/worker.py` 独立线程不读 World、不写 Blackboard。意图落地由主循环做，worker
  只做翻译。
- **planner 是「谁做」的唯一权威**：可达性、菜谱、成本、紧迫度这些物理证据都在 planner；
  LLM 只做两层翻译——把 P1 的话翻成意图，把 planner 的校验结果翻成人话。
- **硬/软分离**：做/禁=硬闸（planner 硬指令/硬压制），分工=软偏好，补位=显式截止闸；
  三者不再揉进同一个软权重。
- 复用 `ai/space/regions.py`（`reachable_by`/`on_far_side`）、`ai/space/reachability.py`
  （`field_for`/`_interact_goals`）、`ai/revenue/throw_supply.py`、`ai/query/recipes.py`
  的现成物理判据，不另起一套测量标准。

## 5. 设计

### 5.1 分工单位 = 动作（= 站点）

`target` 从「物料整链」换成「**动作**」，一个动作绑定一个站点类型，站点类型决定谁能做：

| 动作 | 站点 | 对应 task 类型（举例） | 是否 LLM 可 assign |
|---|---|---|---|
| 取料 | 料箱 | `FetchToBoard`/`FetchToCooker`/`FetchToCarrier`/`Prefetch` | **否**（planner 自动归位） |
| 切 | 砧板 | `Chop` | 是 |
| 下锅（炸/煮/烤） | 灶/炸锅/烤箱 | `FetchToCooker`/`FillCooker`/`PlaceCarrierInCooker` | 是 |
| 拌 | 搅拌站 | `Mix` | 是 |
| 装盘/盛盘 | 盘/出餐台 | `FetchToPlate`/`TakeCookedToPlate`/`PlaceCleanPlate` | 是 |
| 送餐 | 出餐口 | `DeliverPlate` | 是 |
| 洗盘 | 洗碗池 | `WashPlate` | 是 |

「动作=站点=边」三者同构：分割图上「你负责切」自动等于「你负责木筏」（砧板只在木筏）；
连通图上「你负责切」依然成立（不需要「边」）。**物料不再作为分工单位**，降级为可选限定词
（只在 `now`/`stop` 里出现，见 §7.2）。

### 5.2 四个行为：判 / 做 / 分工 / 禁

P1 的一句话，LLM 解析成**意图**（动作 + 性质 + 可选方向/限定词），planner 校验并落地，
结果回填给 LLM 措辞。四个性质：

1. **判（隐式，始终在）**：planner 对每个意图判可行性——P2 够不够得着这个动作的站点、
   这关有没有这道菜/料。不可行 → 拒绝并给出理由，LLM 如实说为什么（「我够不着土豆，你
   在厨房扔给我」）。
2. **做（now，一次性硬指令）**：planner 当场选对 task 立刻执行，命中即消费（复用现有
   `_select_imperative` 的硬闸思路，但作用域从「物料」改「动作」，带可选 item 限定选对
   task，见 §7.2）。执行完即失效，不持久。
3. **分工（assign，持续软约束）**：**双向**——`assign(P2, 动作)` = 「你负责 X」（软
   direct，P2 持续做）；`assign(P1, 动作)` = 「X 我来」（软 claim，P2 避开、截止时补位）。
   校验「这个动作的站点在 P2 可达侧」；跨边动作（站点在 P1 侧）校验不过，拒绝并说明。
4. **禁（stop，硬压制 + TTL）**：接 `_is_stopped` 硬否决，30 秒后自动解除（沿用现有
   `stop` 的 TTL 语义）；救援动作免疫。**不补位**——P1 说「先别做」就是 30 秒别碰，到点
   自动恢复（见 §7.4）。

### 5.3 取料/搬运不暴露，planner 按「料源可达性」归位

搬运/取料**不作为 LLM 可认领（assign）的动作**。它绑定的是**料源**那个站，不是目的地：

- 规则：**谁够得着料箱，谁取料**。分割图上料箱在厨房（P1），所以 P1 取料 + 扔上木筏，P2
  接住 + 切——跨边搬运天然被可达性拆成「上游取+投、下游接」。
- 连通图上两边都够得着料箱时，按**料源距离**归位（谁离料箱近谁取），planner 按距离场
  自动算——「谁近谁取」，同样不需要 LLM 指定。
- （本方案在 brainstorm 中纠正过一个说法：之前「搬运归目的地动作的 owner」在分割图上会
  让 P2 去够不着的厨房取料，是错的；正确的是「按料源可达性归位」。）

取料仍是 planner 内部的一个「动作」概念（用于 help_request、投掷、作用域编译），只是
**不进入 LLM 的 assign 枚举**。

### 5.4 跨边交接：不算分工单位，是可请求的一次性动作

投掷/渡运/共享台是两边动作之间的**接缝**，谁手里有料谁投，不做成分工单位。存在**两套
动作集合**：

- **可分工动作（LLM 可 assign）**：切/下锅/拌/装盘/送餐/洗盘（6 个，取料除外）。
- **可请求动作（一次性 now）**：上面的 6 个 + 投掷/渡运（交接）。救援动作（灭火等）planner
  自动硬扛，语音喊了也只是确认，不单独成类。

「把切好的扔回来」是「做」（一次性请对方投），不是「分工」（不能说「投掷归你」）。

### 5.5 P2→P1 请求与 P1→P2 指派统一

现有 `help_request` 的触发（`top_help_request`/`frontier_steps`/`p1_saves_enough`）保留，
但「挪走」的落法与 P1→P2 的「分工/做」统一成**同一个 request 概念**：

- P1→P2：speech → LLM 提意图 → planner 校验 → 判/做/分工/禁。
- P2→P1：planner 判「P1 更划算 / P2 够不着」→ LLM 只措辞（「帮我拿土豆」）。

两条路落进同一套 `Preference`/硬闸，planner 不分来源。「让给 P1」的语义**保持软 claim**
（不是硬 stop），但权重从 -1.0 加强到足够让 P2 平时避开；补位只走显式截止闸（见 §7.4）。
这样「喊了照做」被修掉，同时保住「订单收尾补位」。

### 5.6 新工具（替换 `update_duties`）

删掉 `update_duties`，开一个动作级的新 tool（名字与 schema 形状由 plan 定，语义如下）：

- 参数语义：`性质`（`now`/`assign`/`stop`/`cancel`，对应 做/分工/禁/撤销）+ `动作`
  （动作枚举，见 §5.1）+ `方向`（assign 时：P2/P1，见 §7.1）+ 可选 `item`（now/stop 用，
  见 §7.2）。`assign` v1 不带 material 字段。
- `cancel` 覆盖「算了别切了」「不是切是下锅」：撤销上一条、或同目标重新指派即覆盖（从
  `update_duties` 的 edit/remove/同 target 改写搬过来）。
- 校验：planner 判 `动作` 的站点是否在 P2 可达侧、菜谱是否有对应料/菜；结果回填 tool 消息，
  LLM 据实措辞（成功确认、被拒如实说明，不再「先答应再落空」）。
- 只做**动作级**，不做物料级分工、不做数量/序列。

### 5.7 硬 / 软分离（不再揉进一个权重）

- 「做」「禁」= 硬：planner 硬指令闸 / `_is_stopped` 硬否决，命中即生效、不可被订单紧迫度
  压过（救援类除外）；「禁」30s TTL 到点自动解除，不补位。
- 「分工」= 软：动作级偏好，持续加分/减分，可被订单紧迫度影响；「让给 P1」的 claim 权重
  加强（§7.4），但仍走打分路径、非硬否决。
- 「补位」= 显式截止闸：只在订单真的要崩时放行被分工让出的动作（现有 `_rescue_gate_open`
  + L0–L2 顶层免疫），并 `rescue` 事件如实播报「来不及了我来」——**不再靠 -1.0 软权重默认
  漏给 P2**。

## 6. 验证

- 单测：
  - **动作级作用域编译**：`动作 → 一组 task 类型` 的 scope 正确；`scope_matches` 命中
    对 task；物料级 target 被移除。
  - **判**：P2 够得着/够不着的动作分别通过/拒绝；这关没有的料/菜被拒并给出理由。
  - **做**：`now` 命中 → planner 选对 task（正确动作、正确站点、正确 item），执行完即失效；
    `now` 带 item 时（「去切鸡块」）选对 item、不带 item 时按打分选最优。
  - **分工**：`assign(P2, 动作)` 落 direct 偏好；`assign(P1, 动作)` 落 claim 偏好；跨边动作
    （站点在 P1 侧）被拒并说明。
  - **禁**：`stop` 接 `_is_stopped` 硬否决 + TTL 到期解除；救援类免疫；不补位。
  - **撤销/覆盖**：`cancel` 撤销上一条；同目标重新指派=覆盖。
  - **help_request 硬/软分离**：P2 求助的「让给 P1」编译成加强 claim（非 -1.0），补位只走
    截止闸；正常（非截止）情况下 P2 不「喊了照做」。
- 离线：`tools/tree_viz.py` 用 Rapids_2_1、Mine_2_4、Sushi_1_4 真实帧，确认分割图
  「动作=边」分工、连通图「动作=站点」分工、跨边交接只作为一次性请求。
- 实机：2-1 说「你负责切我负责炸」→ P2 在木筏切、P1 在厨房炸，双向投掷；说「去切鸡块」
  → P2 立刻切对；说「先别切」→ P2 停手、30 秒后恢复；说「我够不着的活」→ P2 如实回话。
- 回归：`python3 -m pytest tests/` 全绿；相关 spec/AGENTS.md 与代码注释同步更新。

## 7. 我替你做的判断（builder review 后补，可改）

1. **「我来切」= `assign(P1, 切)`（双向分工）**。旧 `leave_to_p1` 并入 `assign` 的「方向」
   字段：`assign(P1, 动作)` = 软 claim（P2 避开、截止补位），`assign(P2, 动作)` = 软 direct
   （P2 负责）。不单设「leave_to_p1」档位。
2. **`now`/`stop` 带可选 item 限定，`assign` 纯动作（v1）**。「去切鸡块」需要 item 才能
   选对 task（2-1 土豆鸡块都要切）；「你负责切」则是动作级（所有料的切）。`assign` 的
   material 字段 v1 不加。
3. **取料不进入 LLM 的 assign 枚举**，由 planner 按料源可达性归位；仍是 planner 内部的
   动作概念（help_request/投掷/作用域编译用）。§5.4 的可分工动作列表不含取料。
4. **「让给 P1」保持软 claim、权重加强（从 -1.0 上调，具体值 plan+实机定），补位只走
   现有截止闸 + L0–L2 免疫；「禁/stop」= 硬 + 30s TTL、不补位**。这样避免把 `_is_stopped`
   从可行性否决挪进打分/加闸例外的大改；「喊了照做」靠加强 claim 在正常（非截止）情况下
   消除，截止时仍能补位。
5. **assign = 动作级（该类型所有实例）**；判 = 「至少一个实例可达」；做 = planner 在候选里
   按打分 + (可选 item) 选一个最优实例，不指定具体站（P1 说话不会点名「3 号灶」）。
6. **动作枚举 = 切/下锅/拌/装盘/送餐/洗盘（6 个）**；`Mix`（拌）加入；`MergePlates`/
   `ResetPlate`/`Discard`/`StashHeld`/`SendAcross` 归 auto_only 或跨边交接，不进 assign 枚举。

## 8. 已拍板（2026-11-04）

- 分工单位 = **动作（=站点）**，物料不做分工单位（只在 now/stop 做 item 限定）。
- 四个行为：**判 / 做 / 分工 / 禁**；`update_duties` 删除，换动作级新 tool。
- 取料/搬运**不暴露给 LLM**，planner 按**料源可达性**归位。
- 投掷/渡运**不算分工单位**（接缝），但可作为一次性「做」的请求对象；两套动作集合分开。
- P2→P1 请求与 P1→P2 指派**统一**成同一 request 概念；「让给 P1」保持软 claim 但加强权重。
- 硬/软分离：做/禁=硬闸，分工=软偏好，补位=显式截止闸。
- 撤销/覆盖语义保留（`cancel`）。
- 开发在**当前分支**进行，可 commit，不 push。


## 9. 场景示例（完整流程）

每个场景走完整条链：P1 说话 → LLM 解析意图 → planner 判 → 落地 → P2 回话。动作取 §5.1 的
6 个可分工动作（切/下锅/拌/装盘/送餐/洗盘）；取料、投掷由 planner 自动归位，LLM 不声明。

### 场景 1：2-1 开局分工（分割图，跨边接力）

**P1 说**：「这把你负责切、我负责炸。」

- 解析：`assign(P2, 切)` + `assign(P1, 炸)`。
- 判：切↔砧板只在木筏（P2 侧）→ 通过；炸↔炸锅只在厨房（P1 侧）、方向是 P1 → 通过。
- 落地：P2 落 direct(切)、claim(炸)。取料↔料箱在厨房 → P1 取料 + 扔上木筏；装盘/送餐↔
  厨房 → P1；投掷是接缝，P1 扔生料、P2 扔切好的。
- P2 回话：「好，我在木筏切，你在厨房炸，我切好扔回去。」

（P1 只说了「切」「炸」两个分工动作，取料/装盘/送餐/投掷由 planner 按「动作=站点=边」
自动补全，LLM 不重复声明。）

### 场景 2：2-1 「你负责薯条」被拒（物料级分工不可行）

**P1 说**：「这把你负责薯条。」

- 解析：意图是物料（薯条），不是动作。
- 判：拒绝——薯条是一条物料链，跨「厨房料箱→木筏砧板→厨房炸锅」两边，P2 无法独自完成；
  新模型不做物料级分工。
- 落地：无（拒绝）。
- P2 回话：「薯条得咱俩接力：你在厨房拿土豆扔给我，我切，切好扔回去你炸。」

### 场景 3：2-1 「去切鸡块」（做 + item 限定，选对 task）

**P1 说**：「去切鸡块。」

- 解析：`now(切, item=鸡块)`。
- 判：鸡块这关有、砧板在木筏（P2 侧）可达 → 通过。
- 落地：planner 硬闸选中 `Chop:鸡块`（不是土豆），立刻执行，执行完失效。
- P2 回话：「这就去切鸡块。」

### 场景 4：2-1 「你去拿个土豆」被拒（P2 够不着）+ 反请 P1

**P1 说**：「你去拿个土豆。」（土豆在厨房料箱，P2 在木筏）

- 解析：`now(取料, item=土豆)`。
- 判：取料↔料箱在厨房（P1 侧）、P2 够不着 → 拒绝，理由「料源在 P1 侧」。
- 落地：无；同时 planner 判「P2 够不着土豆、P1 够得着」→ 触发 P2→P1 的 help_request（
  §5.5），LLM 措辞请 P1 扔。
- P2 回话：「我够不着土豆，你在厨房拿个土豆扔给我。」

### 场景 5：2-1 「先别切」（禁 + TTL）

**P1 说**：「先别切鸡块。」

- 解析：`stop(切, item=鸡块)`。
- 判：通过。
- 落地：planner 硬压制 `Chop:鸡块` 30 秒（`_is_stopped`），P2 转做别的；30 秒后自动恢复，
  不补位。
- P2 回话：「好，先不切鸡块了。」

### 场景 6：连通图 Mine_2_4 「你负责切，我负责煮煎」（动作分工，无投掷）

**P1 说**：「你负责切，我负责煮和煎。」

- 解析：`assign(P2, 切)` + `assign(P1, 下锅)`。
- 判：连通图，切↔砧板、下锅↔灶两边都能走 → 都通过。
- 落地：P2 落 direct(切)、claim(下锅)。取料按料源距离归位——蘑菇/饼皮在左（P2 近）→ P2
  取；米/肉在右（P1 近）→ P1 取，各自取到中间步行交接（无投掷）。装盘/送餐 planner 自动
  归位。
- P2 回话：「好，我切，你煮煎装盘。」

### 场景 7：改口 / 撤销（cancel）

**P1 说**（先）：「去切鸡块。」（几秒后）「算了，别切鸡块了，去切土豆。」

- 解析：第二条 = `cancel(上一条 now(切,鸡块))` + `now(切, item=土豆)`。
- 判：土豆这关有、砧板可达 → 通过。
- 落地：撤销第一条 now，硬闸改选 `Chop:土豆`。
- P2 回话：「好，改切土豆。」

### 边界说明（v1 诚实标注）

「你负责左边 / 右边」这类**区域级**说法，在连通错位图（Mine_2_4、Sushi_1_3/1_4）上更
贴切，但它需要「动作×料」或「区域→动作集」的展开才能精确落账：v1 先把**纯动作级**跑通
（如场景 6 用「你负责切我负责煮煎」表达），区域级说法由 LLM 引导到动作级、或留 v2 再做。


## 10. P2 主动发言示例（proactive speech，不等 P1 先开口）

P2 所有主动开口统一走「planner 判 → LLM 措辞」路径（LLM 不决策、只翻译）。本次**新增一项
「开局分工」**，其余沿用既有事件。

### 10.1 开局分工（新增）

**触发**：开局拿到 level 帧后，planner 算出本关的「动作→边」切分；若存在**干净切分**（某
动作的站点整类聚在一侧、另一动作聚在另一侧，或分割图的一边够不着），P2 主动说一句分工
建议；否则（对称 / 无干净切分）不开口。

**怎么算（复用站点位置/可达性，零新增物理判据）**：
1. 枚举 `world.stations`，按站点类型分组：料箱→取料、砧板→切、灶/炸锅/烤箱→下锅、
   搅拌站→拌、盘/出餐台→装盘、出餐口→送餐、洗碗池→洗盘。
2. 对每种站点类型，判它的站点**整类聚在哪一侧**：全部或绝大多数在左半 → 归左玩家、
   在右半 → 归右玩家、分散在中线 → 共享（分割图按可达性一边够不着）。
3. 存在「归左玩家」与「归右玩家」的动作 → 有切分 → 开口；否则 → 不开口。
4. 汇总切分交给 LLM 措辞一句；共享动作留给 planner 默认（谁近谁做）或 P1 显式 assign。

**例子**（重核自 `docs/map/*.md` / trace，P1 在左、P2 在右）：
- 2-1（分割图）：砧板(切) 只在木筏 → P2；料箱(取料)/炸锅(下锅)/盘(装盘)/出餐口(送餐)
  在厨房 → P1。于是：「我切你炸——你在厨房拿土豆鸡块扔给我，我切好扔回去。」
- 1-3（连通错位）：料箱/砧板/出餐在左、灶/黄瓜箱/洗碗在右 →「你切和取料，我煮和洗盘」。
- 1-4（连通错位）：料箱/洗碗在左、砧板/灶在右 →「你取料洗盘，我切煮装盘」。

不触发（无干净切分）：1-1（对称）、1-2（料箱中线、砧板上排、灶下排，上下分层≠左右出生）。

P1 不说话 → 就按这句自然分工跑（= planner 默认可达性）；P1 之后说话 → 覆盖。

**动态地图（2-6 = Mine_2_6）**：单主网格、无移动平台/传送带，但地板分段、有窄口
（≈gx=0, gz=-4），「动态」= 玩家碰撞使可达性逐帧变。三层机制天然覆盖（分工软偏好自动
fallback + planner 每拍重算可达性 + help_request 求跨边运输），无需新代码。约束：**开局
分工只基于当前帧快照、是软建议，动态图不承诺长期成立**。

### 10.2 全部主动发言（总表）

| 事件 | 触发 | 例子 |
|---|---|---|
| 开局分工（新增） | 开局算出自然切分 | 「我切你炸，你扔料给我、我切好扔回去」 |

### 10.3 P2 邀请 P1 协助的 case（help_request 具体关卡）

触发两类（§5.5 保留，源自 2026-11-02 期全量 fixture 扫描）：
- **分割图**：P2 够不着料源/站、P1 够得着 → **必喊**（结构性）。
- **连通图**：两边都够得着，但 `P2 − P1 ≥ 8 步` → 喊（P1 明显更划算）。

| 关卡 | 请 P1 做 | 触发 | P2 说 |
|---|---|---|---|
| Rapids_2_1 (2-1) | 把土豆/鸡块扔上木筏 | P2 够不着料箱 | 「帮我拿个土豆扔过来」「鸡块也扔过来」 |
| Wizard_3_1 (3-1) | 把面团/奶酪放中间共享台 | P2 够不着 | 「把面团放中间台给我」 |
| Wizard_5_5 (5-5) | 把生菜/面包送上楼 | P2 够不着（高度差） | 「把生菜送上来」 |
| 3_6_Dynamic (3-6) | 把米送过来 | P2 够不着 | 「把米送过来」 |
| Mine_2_4 (2-4) | 盛熟肉 / 送米饭 | P2−P1 ≥ 8 步（跨区 ≈10~13 步） | 「帮我把肉盛了」「把米饭送过来」 |

不触发（阈值以下，不喊）：
- Wizard_3_2 (3-2) 面团：P1=1 步 vs P2=3 步，差 2 步 < 8 → 不喊，P2 自己做。

每次冷却窗口**最多喊一条**、同 (料/站) 未解决不重复；P1 不理 → P2 解除「让给」自己兜底
（§5.5）。落法与 P1→P2 的「分工/做」统一：P2 求助 = 给自己落一条 `assign(P1, 动作)`
（加强 claim，§7.4），不再用 -1.0 软权重。
